## 二、核心手册（精读优先级排序）

### 第一梯队

**1. [RichardXu001/the-fde-handbook](https://github.com/RichardXu001/the-fde-handbook)** · 72★ · 中英双语
- 《FDE：企业 AI 落地实战手册》开源手册
- 这是 FDE 领域**最接近正式出版物**的开源手册，章节结构完整
- 适合当作主教材反复读

**2. [goday-org/FDE-Handbook](https://github.com/goday-org/FDE-Handbook)** · 23★ · 🇬🇧
- 生产就绪手册，面向已准备交付的工程师
- 覆盖：企业 landing zone、VPC 服务边界、权限模型
- 特点：**技术护栏讲得具体**，不是泛泛而谈

**3. [dawei008/fde-book](https://github.com/dawei008/fde-book)** · 22★ · 🇨🇳
- OpenBook Vol II · AI 应用的落地工程学
- 核心公式：**`Outcome = Harness × Customer`**
- 这个公式值得单独想清楚：结果 = 工具链 × 客户。任一为 0 则结果为 0
- 所以「只用工具不去客户现场」和「只见客户不建工具」都做不出结果

### 第二梯队

**4. [feigaobox10/fde-reader](https://github.com/feigaobox10/fde-reader)** · 131★ · 🇨🇳
- 《FDE 入门到精通》开源电子书，八堂课
- 主题聚焦「将 AI 送进客户现场」

**5. [jaycehuang/fde-handbook](https://github.com/JayceHuang/fde-handbook)** · 39★ · 🇨🇳
- FDE 现场工程手册

**6. [jiji262/fde-guide](https://github.com/jiji262/fde-guide)** · 26★ · 🇨🇳
- 《从零到 FDE：AI 时代前线部署工程师转型实战课》

**7. [anjor/fde-advisory-materials](https://github.com/anjor/fde-advisory-materials)** · 16★ · 🇬🇧
- Anjor Kanekar（Platypus Technologies）的 FDE 咨询方法论开源材料
- **特殊价值**：来自「设计 FDE 组织」的人，而非「执行 FDE 工作」的人
- 核心议题：FDE 该归 GTM 还是归工程？该服务产品还是服务客户？

**8. [dgannon/Forward-Deployed-AI-Engineer-Playbook](https://github.com/dgannon/Forward-Deployed-AI-Engineer-Playbook)** · 7★ · 🇬🇧
- FDE 的全套「打法」手册

**9. [FDEInfra/FDEBook](https://github.com/FDEInfra/FDEBook)** · 53★ · 🇬🇧
- OpenFDE 开放知识库与社区，配套站点 open-fde.com

## 四、行业与技术专题

### Palantir Ontology 与 AIP（源自 FDE 的核心技术语境）

| 资源 | Star | 说明 |

| [manualbomi/palantir-foundry-fde-playbook](https://github.com/manuelbomi/palantir-foundry-fde-playbook) | 1★ | Palantir Foundry 全流程案例研究 + 通用化 FDE playbook |
| [s-andthat/palantir-ai-fde-library](https://github.com/s-andthat/palantir-ai-fde-library) | 11★ | Palantir AI FDE 的社区 prompt 与 Agent 架构库 |
| [hasura/axiom](https://github.com/hasura/axiom) | 13★ | PromptQL 的 FDE demo kit |

> 💡 **为什么值得学 Ontology**：Ontology（本体）是 Palantir FDE 方法论的底层 —— 传统数据平台告诉你「有多少数据」，Ontology 回答「这个组织里什么东西是什么、如何流转、谁对什么负责」。
> 不理解 Ontology，就理解不了为什么 Palantir 的 FDE 能在军事、医院、制造现场工作。

### 安全与合规部署

[Awesome-FDE-Roadmap](https://github.com/pierpaolo28/Awesome-FDE-Roadmap) 中这部分内容非常独特，值得单独记录 —— **「离线与战术边缘部署」是 FDE 最难的工作**：

| 术语 | 含义 |
|------|------|
| SCIF / 潜艇 / 前沿作战基地 / 离线工厂车间 | 互联网到不了的地方，标准云方案全部失效，必须**把平台搬过去**而不是连过去 |
| ATO | 授权运营（Authority to Operate），政府网授权，走 NIST RMF，通常 **6–18 个月** |
| DoD Impact Levels | IL2（可公开）/ IL4（CUI 受控）/ IL5（更高敏感 CUI + 任务关键）/ IL6（最高机密），决定能用哪些云（GCC High、AWS GovCloud、Azure Government）与网络 enclave（NIPRNet、SIPRNet） |
| FedRAMP High vs Moderate | 多数生成式 AI 服务仅达 Moderate —— 这是国防负载的硬性阻碍，承诺功能前必须查 Marketplace |
| STIGs | DISA 发布的逐行加固清单，CI 必须产出 STG 合规产物否则 ATO 会驳回 |
| ITAR / EAR | 出口管制：模型若在 ITAR 受控数据上训练，**权重本身即受管制**，永不可交付给非美国人员 |
| CMMC 2.0 | 国防承包商认证，Level 2 是实际门槛 |

> 这段内容解释了为什么 FDE 这个岗位「难」 —— 有时候难点根本不在 AI，而在能否拿到 ATO。
