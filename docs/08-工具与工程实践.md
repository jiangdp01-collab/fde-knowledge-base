## 三、实战模拟与训练环境

### fde-gym ⭐ 独特价值

| 项目 | 信息 |
|------|------|
| **仓库** | https://github.com/deeplethe/fde-gym |
| **Star** | ⭐ 92★ |
| **语言** | TypeScript |
| **定位** | **LLM 时代的在线判题器** |

**核心机制**：每个案例都是一次**真实客户交付**，你配合一个编码 Agent 一起完成。

**为什么独特**：
传统的刷题平台（LeetCode 模式）与 FDE 的实际工作几乎无关。fde-gym 把评测单位从「算法题」换成了「客户交付任务」，这更接近 FDE 面试第三轮的实际考法。

## 六、技术栈速查（来自 Awesome-FDE-Roadmap 与 Dexity JD 分析）

| 层次 | 技术 |
|------|------|
| **语言** | Python（主力，60% JD 默认要求）、TypeScript/JavaScript（前端）、Java/C++（Palantir 式岗位常见） |
| **API 与集成** | REST API、gRPC、Webhooks、事件流 |
| **数据** | ETL/ELT、Schema 设计、Postgres、数据仓库 |

## 七、工具链搭建建议

### 个人 FDE 工具箱（轻量起步）

```
1. FDE 方法论     → 读 anjor/fde-advisory-materials（开源、有深度）
2. 访谈记录       → xinnan-tech/xiaozhi-fde-talk
3. 方案与交付     → FDEOps 或 fdestack（选其一即可）
4. 动手练习       → ai-engineer-notebooks（概念验证）→ fde-gym（交付训练）
5. 作品集模板     → 按 alphalab 的 case-study 结构
```

### 团队级工作台

```
1. 机会发现与调研 → gxfde/fde-workbench
2. 交付流程标准化 → 团队自建 SOP（参考 Platypus 方法论）
3. 评测体系       → 自建 golden-set + 持续回归
4. Agent 能力     → sofagent / agnes-harness（可插拔架构更易扩展）
5. 案例沉淀       → 自建 case library
```

### 选型建议

| 你的情况 | 建议 |
|---------|------|
| 刚了解 FDE，暂不落地 | 只读 `anjor/fde-advisory-materials`，理解方法论即可 |
| 准备转型，想练手 | `ai-engineer-notebooks` + `fde-gym` |
| 已经在做 FDE 交付 | FDEOps / agnes-harness + 自建评测体系 |
| 团队要建 FDE 能力 | `gxfde/fde-workbench` + Platypus 的组织设计材料 |
| 企业采购外部服务 | 见 [07 章的决策清单](./07-咨询与服务商.md#四采购决策清单) |

## 八、甄选工具时的判断标准

FDE 工具目前还很年轻（多数诞生于 2026 年），甄选时建议看：

- [ ] **Star 数与提交活跃度** —— FDEOps 962★ vs 大多数 10★ 以内，说明生态差异巨大
- [ ] **是否有真实用户反馈**（Issues 里有没有真实讨论）
- [ ] **License 是否允许商用** —— CC BY 与 MIT 差别很大
- [ ] **是否开源方法论本身**，而不只是工具
- [ ] **是否包含评测环节** —— 只做生成不做验证的工具，对生产交付价值有限
- [ ] **数据是否本地** —— 涉及客户数据时，这是硬约束
